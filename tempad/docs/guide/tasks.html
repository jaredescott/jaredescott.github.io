Tasks ​

The Tasks view is where you create and triage work before it lands on the calendar.

Layouts ​

Switch layouts with the List, Board, and Matrix tabs in the Tasks toolbar. When Gantt view (beta) is enabled in Settings, a Gantt tab appears as well:

List mode ​

Best for fast editing: search, complete tasks, and review metadata (due date, duration, list, priority, Eisenhower quadrant badge).

Kanban mode ​

Columns follow your lists. Drag cards between columns to change list assignment or stage-style workflow.

Eisenhower matrix ​

Sorts tasks into four quadrants by urgency and importance so you can decide what to do first, schedule, delegate, or defer.

QuadrantLabelTypical use
Q1Do firstUrgent and important — deadlines, crises
Q2ScheduleImportant, not urgent — goals and planning
Q3DelegateUrgent, not important — interruptions, quick asks
Q4LaterNeither urgent nor important — batch or drop

How placement works

  • Turn on Use task priorities in Settings to treat ASAP as always urgent/important (Q1).
  • Mark Important or Urgent on a task in the editor for explicit matrix placement.
  • Without flags, due date drives urgency (due today or within the next couple of days counts as urgent).
  • Drag cards between quadrants to update importance/urgency flags.

Settings

  • Show inbox tasks in Eisenhower matrix — include inbox/backlog items in the matrix (off by default).
  • List filters still apply: use sidebar chips to focus on Work, Personal, or Inbox.

New users get sample tasks in each quadrant when the app seeds demo data on first load.

Gantt mode (beta) ​

Off by default. Turn on Gantt view (beta) under Settings → Scheduler, then open Tasks and choose the Gantt layout tab.

Gantt is a timeline view of work that TemPad has already placed on your calendar — not a separate scheduling surface.

What appears

  • Auto-scheduled tasks that have at least one scheduled block (from Reschedule or prior scheduling).
  • One horizontal bar per task from the earliest block start to the latest block end (split tasks show as one combined bar).
  • List color on the bar and a dot beside the task name in the sidebar (hidden in zen mode).
  • Filled portion of the bar = progress (elapsed time in the scheduled window, or subtask completion when Subtasks (advanced) is on).
  • Dependency arrows between tasks when depends on links exist among visible rows.
  • Today column highlight and vertical line on the timeline.

What is excluded

  • Routines, inbox-only tasks, fixed-time tasks without scheduled blocks, and subtasks (parents only — same as other task layouts).
  • Tasks that are not auto-schedule.

Interaction

  • Click a task name (left) or its bar to open the task editor.
  • Use the Tasks search box and sidebar list filter — same as List/Kanban/Matrix.
  • Bars are read-only on the Gantt chart; change timing on the Calendar (drag blocks) or edit the task, then Reschedule.

Empty state

If Gantt shows no rows, run Reschedule on the Calendar after ensuring tasks use Auto-schedule and have due dates and duration.

Beta scope

  • No drag-to-reschedule on the Gantt chart itself (use Calendar).
  • No separate GCal export of Gantt segments.

Scheduling mode (task editor) ​

Use the Scheduling dropdown when editing a task:

  • Auto-schedule — TemPad finds time on your calendar within scheduling hours.
  • Inbox — capture work for triage; it stays off the calendar until you promote it (switch mode, or set a due date / ASAP / Important+Urgent so it graduates on save).
  • Fixed times — you set start and end; TemPad does not auto-place the task.

Inbox and auto-schedule cannot apply at once. New tasks created while the Inbox filter is active start in Inbox.

Creating tasks ​

When adding a task, set at minimum:

  • Title
  • List (or default list from Settings)
  • Due date — required for scheduling placement
  • Duration — minutes of work the scheduler should allocate

Optional: priority (if enabled in Settings), Important / Urgent for Eisenhower, dependencies, splittable flag, notes, repeat rules.

Smart editor layout (primary vs More options) ​

When Smart task editor is on in Settings → Scheduler (default), the task editor shows a small primary set of fields and collapses the rest under More options.

  • Primary always includes essentials such as list, scheduling mode, duration, and due date.
  • More options holds fields you use less often (repeat, dependencies, splittable, notes, and similar).
  • Which fields stay primary is inferred from your saved tasks (roughly: fields you use on at least 15% of tasks, once you have at least five tasks). The layout refreshes when you save a task and when you open the editor.
  • Editing a task that uses a field tucked under More options expands More options automatically so nothing is hidden.
  • New accounts with fewer than five tasks see all fields until there is enough history to collapse.
  • Turn off Smart task editor or turn on Show all task fields to always see the full form.

List filters ​

Use sidebar list chips to focus on one list (including Inbox). Filtering hides other lists from task views and can affect what you see on the calendar sidebar context.

Subtasks (advanced) ​

Off by default. Turn on Subtasks (advanced) under Settings → Scheduler to break a parent task into ordered steps.

  • Add subtasks on a parent task in the editor (title and duration per step).
  • Only the parent is auto-scheduled; subtasks inherit list and scheduling hours and do not schedule on their own.
  • Parent duration is the rollup of incomplete subtask durations (read-only while subtasks exist).
  • On the calendar, subtasks appear as chips inside the parent’s scheduled time. When the parent is splittable and the scheduler places it in multiple blocks, subtasks are distributed across those blocks in order—each block shows only the steps assigned to that slot (a step may still appear if it is longer than the slot). When the parent fits in a single block, all steps appear together. Click a chip to open that subtask; click the parent chrome to edit the parent.
  • In list layout, expand a parent row to see nested subtasks; a 2/5 badge shows completion progress.
  • Completing all subtasks marks the parent complete; completing the parent completes all subtasks.
  • With the setting off, subtasks stay in your data but are hidden from task lists until you turn the feature back on.

Dependencies ​

Link tasks so one must finish before another starts. The scheduler uses a topological sort; cycles are rejected.

Drop task onto task (Settings → Theme): In List, Kanban, and Matrix, drag one incomplete task onto another. Default Create subtask nests the dragged task under the target (requires Subtasks (advanced)). Create dependency links them instead.

Dependency drag direction (Settings): when drop mode is Create dependency, controls whether the target depends on the dragged task or the reverse — match your mental model and stick to one setting.

Repeating tasks ​

Tasks with a repeat rule get one scheduled occurrence per due date. To remove part of the series, open a block on the Calendar and use Delete → This occurrence, This and following, or All occurrences (see Calendar — Deleting recurring items).

Completion and auto-schedule ​

Completing a task removes it from scheduling. Editing due date, duration, list hours profile, or dependencies triggers a reschedule pass (same as adding/deleting tasks).

See Calendar for placement and lock behavior after tasks are scheduled.
